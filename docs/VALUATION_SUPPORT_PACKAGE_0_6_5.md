# Valuation Support Package 0.6.5

This document does not establish market value.
It supports technical diligence discussion only.

Not authorized for human use. For medical/regulatory review only. Requires external IDE/ITA/IRB/REB approval before any human-subject activity.

## 1. Technical summary
0.6.5 organizes the software as a Medical Review Candidate / Preclinical R&D Package with explicit release gates, QMS artifacts, traceability, and bench/HIL measurement hooks.

## 2. Proprietary architecture
The core technical discussion centers on the neural-chip-only pipeline, explicit ACK, state machine, replay v2, evidence bundle tooling, and bench-only hardware abstraction.

## 3. Critical modules
HumanSubjectUseGate, ReleaseModeLock, MedicalReviewGate, HardwareBenchSessionRunner, P95P99AcceptanceGate, TraceabilityCoverageGate, and SignedEvidenceManifest are diligence anchors.

## 4. Tests and coverage
CTest and static validation summaries are generated by tools/build/run_full_release_validation.py.

## 5. QMS/Risk docs
Open risk, independent review, release record, traceability, safety case, cybersecurity summary, and SBOM artifacts support review.

## 6. HIL/bench evidence
HIL/bench evidence is measured through phantom/loopback sessions with p50/p95/p99 metrics.

## 7. Limitations
External hardware bench validation, independent medical/regulatory review, and signed authorization evidence are not created by the software.

## 8. IP assumptions
Any valuation discussion requires independent IP ownership, freedom-to-operate, and assignment review.

## 9. Remaining external validations
Independent safety, cybersecurity, QMS, regulatory, medical, hardware, and legal reviews remain necessary.

## 10. Why valuation requires independent due diligence
Software evidence can support diligence, but market value depends on IP, team, market, external results, reviewer confidence, regulatory path, and transaction terms.
