# Fuzzing Plan

> Confidentiality: Level 3 — NDA controlled unless otherwise stated.
> Evidence boundary: preclinical R&D software evidence only; fuzzing does not authorize human-use or clinical deployment.

## Initial fuzz targets
| Target | Input corpus | Safety property | Stop condition |
| --- | --- | --- | --- |
| Hardware bench session parser | Valid/invalid JSON manifests | Reject human-subject or unsafe bench fields | No crash, expected rejection reason |
| QMS signature verifier | Signed artifact JSON variants | Placeholder/stale/revoked signatures rejected | No crash, accepted only for trusted non-revoked structure |
| Replay/config ingestion | Replay logs and runtime config files | Deterministic handling and bounded memory | No crash, no state-machine bypass |
| Runtime stage sequencing | Mutated stage names/order | No direct legacy-node bypass | No crash, invariant preserved |

## Corpus seeds
- `clinical_evidence/*.json*`
- `clinical_sessions/*.json*`
- `config/*.json`
- `qms/generated/*.json`
- Minimal malformed JSON and oversized-field variants generated by the fuzz harness.

## Human-use bypass cases
Any mutated input that sets `human_subject_present`, `human_use_enabled`, clinical mode, active stimulation, or missing emergency-stop evidence must remain blocked unless all documented QMS/regulatory prerequisites are valid.
